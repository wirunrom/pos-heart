# 04 Patterns

พฤติกรรมที่ใช้ซ้ำได้ทุกหน้า แต่ละ pattern บอกว่าใช้ component อะไร และ*ห้ามทำอะไร*

## 1. ค้นหาและเลือกรายการจำนวนมาก

- **หน้าขาย:** ช่องค้นหาได้ focus อยู่ตลอด · พิมพ์แล้ว**กรองการ์ดสินค้าทันที** (ไม่ต้องกด Enter) · `Enter` = เพิ่มรายการแรกที่ตรง · ถ้าสแกน barcode ได้ตรงตัวเดียว → เพิ่มลงตะกร้าเลยแล้วล้างช่องค้นหา · ถ้าตรงหลายตัว → เปิดรายการให้เลือก
- **ค้นได้ด้วย:** ชื่อไทย/อังกฤษ, รหัส, barcode, คำย่อ (ในอนาคตอาจรองรับการค้นแบบไม่สนวรรณยุกต์)
- **หน้าจัดการ:** `/` เพื่อ focus ช่องค้นหา · ตัวกรองเป็น chip ที่เห็นได้เสมอ · บันทึกตัวกรองที่ใช้บ่อยเป็น “มุมมอง” ใน SideNav (เช่น สต็อกต่ำ) พร้อมตัวนับ
- **ไม่พบ:** StateView บอกคำที่ค้นและตัวกรองที่เปิดอยู่ + ปุ่มล้างตัวกรอง · ถ้ามีสิทธิ์ ให้เสนอ “เพิ่มสินค้า ‘…’”
- **ห้าม** ใช้ pagination บนหน้าขาย (ให้เลื่อนแทน) · ห้ามล้างคำค้นเองเมื่อเปลี่ยนหมวดหมู่

## 2. กรอกและตรวจสอบข้อมูล

- ตรวจ**ตอนออกจากช่อง** (blur) และตอนบันทึก ไม่ตรวจระหว่างพิมพ์ ยกเว้นช่องเงินที่ต้องแสดงเงินทอนแบบ live
- ข้อความผิดพลาดบอก*สิ่งที่ต้องทำ*: “ราคาต้องไม่ติดลบ” ไม่ใช่ “ข้อมูลไม่ถูกต้อง”
- **MoneyField:** รับเฉพาะตัวเลขและจุด · จัดรูปแบบ `1,500.00` ตอนออกจากช่อง · ห้ามปัดเศษเงียบ ๆ · เมื่อ focus ให้เลือกค่าเดิมทั้งหมดเพื่อพิมพ์ทับได้ทันที
- ช่องที่ไม่บังคับให้เขียน “(ไม่บังคับ)” ไม่ใช้ `*` แทนช่องบังคับ
- เมื่อกดบันทึกแล้วมีข้อผิดพลาดหลายจุด → เลื่อนไปช่องแรกที่ผิด + Banner สรุปจำนวน

## 3. Draft / save / discard / autosave

| ประเภทข้อมูล | พฤติกรรม |
|---|---|
| **บิลที่กำลังขาย** | บันทึกลง SQLite ทุกครั้งที่เปลี่ยน (autosave) — ปิดแอปหรือไฟดับแล้วกลับมาต้องได้บิลเดิม · ไม่มีปุ่ม “บันทึก” |
| **การนับเงิน / ปิดกะ** | autosave เป็น draft พร้อมเวลา (“บันทึกร่างอัตโนมัติ 17:43”) · ยืนยันได้ครั้งเดียวที่ขั้นสุดท้าย |
| **ฟอร์มข้อมูลหลัก** (สินค้า, ตั้งค่าร้าน) | แก้แล้วยังไม่มีผล จนกว่าจะกด **บันทึก** (`Ctrl S`) · แสดง Banner “มีการแก้ไขที่ยังไม่บันทึก” · ปิดหน้าแล้วถามว่าจะ บันทึก / ทิ้งการแก้ไข / แก้ต่อ · เก็บ draft ไว้ในเครื่องเผื่อแอปปิดกะทันหัน |
| **ตั้งค่าเล็ก ๆ** (ภาษา, ธีม, density) | มีผลทันที ไม่ต้องบันทึก |

## 4. งานหลายขั้นตอนและการกลับมาทำต่อ

ใช้ `Steps` เมื่อมี 3–5 ขั้นที่มีลำดับชัด (first-run setup, ปิดกะ, ตรวจนับสต็อก)
แต่ละขั้นบันทึก draft ได้ · ย้อนกลับได้โดยข้อมูลไม่หาย · เปิดแอปใหม่แล้วหน้าแรกเสนอ “ทำปิดกะ #12 ต่อ (ขั้นที่ 2)”
ขั้นที่*ยืนยันแล้ว*ล็อกไว้ และแสดงว่าใครยืนยันเมื่อไร

## 5. การยืนยัน, undo และสิ่งที่ย้อนกลับไม่ได้

| ระดับผลกระทบ | วิธี | ตัวอย่าง |
|---|---|---|
| ย้อนกลับได้ง่าย | ทำเลย + Toast “เลิกทำ” (6 วินาที, `Ctrl Z`) | ลบบรรทัดในตะกร้า, พักบิล, ปิดขายสินค้า |
| ย้อนกลับได้แต่มีผลต่อคนอื่น | ทำเลย + Toast + บันทึกใน audit log | เปลี่ยนราคา |
| **ย้อนกลับไม่ได้ / กระทบเงิน** | Dialog ที่บอก**ผลเป็นตัวเลข** + เหตุผล (เลือกจากรายการ) + ปุ่มชื่อเดียวกับการกระทำ | ยกเลิกทั้งบิล, คืนเงิน, ปิดกะ, ล้างข้อมูล |

ปุ่มใน Dialog ใช้คำกริยาที่ตรงกับการกระทำ (“ยกเลิกบิล” / “ไม่ยกเลิก”) ห้ามใช้ “ตกลง / ยกเลิก” · ปุ่มที่ปลอดภัยได้ focus ก่อน

## 6. งานการเงินและการอนุมัติ

- **4 แนวคิดที่ห้ามปนกัน:**
  **ยอดขาย** (มูลค่าที่ขายได้ ก่อน/หลังคืน) · **รายรับ** (เงินที่รับเข้ามาจริงตามวิธีชำระ) · **เงินสดในลิ้นชัก** (ตั้งต้น + รับเงินสด − คืนเงินสด ± เงินเข้า/ออก) · **สถานะชำระ** ของบิล (ค้าง / บางส่วน / ครบ / คืนแล้ว)
- ทุกตัวเลขสรุปบอกที่มาได้ (แสดงสูตร `= ก่อนคืน − คืน` หรือกดดูรายการ)
- เงินเข้า/ออกจากลิ้นชัก**ต้องมีเหตุผล** · ส่วนต่างตอนปิดกะ**ต้องมีเหตุผล**เมื่อไม่ตรง
- **Approval (Future):** การกระทำที่ต้องอนุมัติ แสดงไอคอนกุญแจ + “ต้องให้ผู้จัดการอนุมัติ” ก่อนกด · กดแล้วเปิดช่องใส่ PIN ใน Dialog เดิม (ไม่ต้องออกจากงาน) · บันทึกผู้ขอ/ผู้อนุมัติ/เวลา

## 7. เลือกหลายรายการและ bulk actions

checkbox อยู่คอลัมน์แรก · `Shift+คลิก` เลือกเป็นช่วง · `Ctrl A` เลือกทั้งหมด*ในผลกรอง* · เมื่อเลือกแล้ว BulkBar แทนที่แถวเครื่องมือ (บอกจำนวน + action + ล้างการเลือก)
action ที่ทำลายข้อมูลใน bulk → Dialog ที่บอกจำนวนและตัวอย่างรายการ · ผลลัพธ์บางส่วนล้มเหลว → Banner “ทำได้ 18 จาก 20 · ดู 2 รายการที่ไม่สำเร็จ”
**บนโหมดสัมผัส:** แตะค้างหรือกด “เลือก” เพื่อเข้าโหมดเลือก

## 8. สถานะออเดอร์, การชำระเงิน และการทำอาหาร/ส่ง แยกกัน

แต่ละบิลมี 3 แกนที่เปลี่ยนแยกกันได้: **Order** (ร่าง → เปิด → ปิด / ยกเลิก) · **Payment** (ค้าง → บางส่วน → ครบ → คืนบางส่วน/คืนทั้งหมด) · **Fulfillment** (รอส่งครัว → กำลังทำ → พร้อม → เสิร์ฟแล้ว / รับแล้ว / ส่งแล้ว)
แสดงด้วย `StatusLine` (badge ได้สูงสุด 3 ตัว เรียงตามลำดับนี้เสมอ) · ห้ามรวมเป็นสถานะเดียว เช่น “เสร็จแล้ว” · ร้านค้าปลีกที่ไม่มีครัวจะไม่แสดงแกน Fulfillment

## 9. งานเบื้องหลัง, การเชื่อมต่อ และ sync

| สถานะ | แสดงที่ | รูปแบบ |
|---|---|---|
| Offline (ปกติในเวอร์ชันแรก) | StatusPill ในแถบบน | จุดกลวง + “ออฟไลน์” — **ไม่ใช่ error** ไม่ใช้สีแดง |
| กำลัง sync (Future) | StatusPill | จุดน้ำเงิน + “กำลังซิงก์ 3” |
| Sync ไม่สำเร็จ / ข้อมูลขัดแย้ง | Banner ในหน้าที่เกี่ยวข้อง + จุดส้มที่ pill | บอกรายการ + ทางเลือก “ใช้ของเครื่องนี้ / ของอีกเครื่อง / รวม” |
| อุปกรณ์ (เครื่องพิมพ์, ลิ้นชัก, สแกนเนอร์) | Banner เมื่อใช้แล้วล้มเหลว · หน้าตั้งค่าอุปกรณ์ | “ขายสำเร็จแล้ว แต่พิมพ์ใบเสร็จไม่ได้” + พิมพ์ซ้ำ |
| สำรองข้อมูล / export | Toast เมื่อเสร็จ + ไฟล์ · Banner เมื่อนานเกิน 7 วัน | |

**กติกา:** งานเบื้องหลัง**ห้ามขัดจังหวะ**การขาย (ไม่มี modal) · ความล้มเหลวของอุปกรณ์ต้องไม่ทำให้การขายที่สำเร็จแล้วดูเหมือนล้มเหลว

## 10. แจ้งข้อผิดพลาดพร้อมวิธีแก้

โครงข้อความ: **เกิดอะไรขึ้น** + **ข้อมูลปลอดภัยไหม** + **ทำอะไรต่อ** (ปุ่ม)
> “พิมพ์ใบเสร็จไม่สำเร็จ · ขายสำเร็จแล้ว · ตรวจกระดาษและสาย แล้ว [พิมพ์ซ้ำ]”

ห้ามโทษผู้ใช้ · ห้ามแสดงรหัสข้อผิดพลาดเป็นข้อความหลัก (ใส่ไว้ใน “รายละเอียด” สำหรับฝ่ายช่วยเหลือ) · ข้อผิดพลาดที่แก้เองได้ไม่ต้องมี Dialog
